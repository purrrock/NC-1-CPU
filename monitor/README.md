# NC-1 Nano-Monitor

Nano-Monitor — минимальная ROM-мониторная программа для учебного 4-битного процессора NC-1.

Монитор позволяет с 16-клавишной hex-клавиатуры:

- загружать машинный код в User RAM вручную (фиксированно с адреса `0x10`, формат COM-файлов);
- запускать загруженную программу;
- загружать бинарные файлы с синхронного накопителя (флеш-карты) прямо в User RAM;
- вводить машинный код вручную с синхронной записью (дампом) потока на накопитель;
- возвращаться из пользовательской программы обратно в монитор.

Монитор работает в System Mode и размещается в System ROM (`0x00..0xEF`).

## Запуск

После аппаратного сброса NC-1 начинает выполнение с адреса `0x00`, где находится Nano-Monitor.
Монитор ожидает одну команду с клавиатуры.
Поддерживаются четыре команды:

| Клавиша | Команда | Назначение |
|---|---|---|
| `A` | `LOAD` | Ручной ввод программы в RAM с клавиатуры (старт с `0x10`) |
| `B` | `RUN` | Запустить программу из RAM (переход на `0x10`) |
| `C` | `TAPE` | Автоматическая загрузка файла с накопителя в RAM |
| `D` | `DUMP` | Ручной ввод с клавиатуры с дублированием на накопитель |

Все остальные клавиши в командном режиме не работают.

## LOAD (Ручной ввод)

Нажмите:

```text
A
```

Монитор переходит в режим ввода машинного кода. Ввод стартового адреса не требуется — пользовательские программы всегда размещаются с базового адреса `0x10` (по аналогии с `.com` файлами в DOS).

Каждый введённый hex-ниббл записывается в последовательные ячейки User RAM. Например, ввод:

```text
A
1 2 3 4 5 6
F 0
```

запишет:

```text
RAM[0x10] = 0x1
RAM[0x11] = 0x2
RAM[0x12] = 0x3
RAM[0x13] = 0x4
RAM[0x14] = 0x5
RAM[0x15] = 0x6
```

Последовательность `F0` является признаком завершения загрузки и в память не записывается.
После ввода `F0` монитор закрывает файл и возвращается в командный режим.

### Как записать `F` как данные

Поскольку `F0` используется как признак конца загрузки, для записи произвольного `F` используется escape-последовательность:

```text
FF
```

То есть `FF` означает «записать литеральный `F`».

Например, чтобы записать машинную программу:

```text
F 4 1 2 F 0
```

необходимо ввести:

```text
A
FF 4 1 2 FF 0 F 0
```

Последнее `F0` завершает ввод.

## DUMP (Интерактивный ввод с сохранением на накопитель)

Нажмите:

```text
D
```

Режим совмещает ручной ввод с клавиатуры и синхронное сохранение данных на внешний накопитель:
Пользователь вводит нибблы с клавиатуры точно так же, как в режиме `LOAD` (с поддержкой `FF` для записи `F` и `F0` для выхода).
Каждый введённый ниббл параллельно записывается в User RAM и на внешний накопитель.
`F0` завершает запись, останавливает накопитель (закрывает файл) и возвращает монитор в командный режим.

## TAPE LOAD (Загрузка с накопителя)

Нажмите:

```text
C
```

Монитор инициирует чтение бинарного файла с внешнего накопителя.
Поток нибблов автоматически считывается с внешнего накопителя и записывается в User RAM начиная с адреса `0x10`.
При достижении конца файла монитор отключает накопитель (закрывает файл) и возвращается в командный режим через `BOOT`.


## RUN (Запуск программы)

Для запуска программы нажмите:

```text
B
```

Монитор аппаратно переключает процессор в User Mode (`M=0`) и безусловно передаёт управление на фиксированный адрес входа через трамплин 
```text
0x10
```

## Индикация

Во время работы четыре 7-сегментных индикатора используются для отображения состояния системы.
Монитор использует механизм динамической индикации (Dynamic Feedback) — в режиме LOAD и DUMP на индикаторе `DISP_1` отображается текущее содержимое RAM, а в момент удержания клавиши оно мгновенно перекрывается вводимым кодом для визуального контроля.

Основная информация:

```text
DISP_3 DISP_2 DISP_1 DISP_0
   адрес     память/    режим
              ввод
```

- `DISP_0`: Текущий режим работы (`0` — ожидание команды, `A` — ручной ввод, `B` — выполнение, `C` — авто-загрузка с флешки, `D` — ввод с дампом).
- `DISP_3 : DISP_2`: Текущий адрес памяти.
- `DISP_1`: Данные в RAM по текущему адресу (или код клавиши при её физическом удержании).

## Требования к пользовательской программе

Программа должна находиться в User RAM и компилироваться с директивой начального адреса `ORG 0x10`.

Основная область пользовательского кода:

```text
0x10 .. 0xDF
```

Адреса `0x01..0x0F` (Zero Page) зарезервированы ABI монитора/ОС и не должны использоваться пользовательской программой без понимания аппаратных соглашений об их сохранении.

Области памяти NC-1:

```text
0x00       Entry Vector (System Bank)
0x01-0x0F  Zero Page / OS state
0x10-0xDF  Program Space (User COM-area)
0xE0-0xEF  Hardware Stack
0xF0-0xFF  MMIO
```

## Возврат в Nano-Monitor

Пользовательская программа должна возвращать управление монитору через инструкцию программного сброса `BOOT`:

```asm
BOOT
```

Выполнение `BOOT` переводит процессор в System Mode (`M=1`) и аппаратно передаёт управление единой точке входа `0x00`.
После этого Nano-Monitor снова переходит в командный режим и ожидает нажатия команды (`A`, `B`, `C`, `D`).

Простейшая программа (`.com` структура):

```asm
ORG 0x10
LDI 0x5
MOV B,A
BOOT
```

## Ограничения

Nano-Monitor предназначен для загрузки и запуска небольших учебных программ.

Загрузка машинного кода за пределы `0xDF` не должна использоваться во избежание повреждения стека.
Аппаратный стек расположен в отдельной странице памяти:

```text
0xE0 .. 0xEF
```

и аппаратно используется инструкциями `CAL`/`RET`/`PHA`/`PLA`. При попытке продвижения указателя адреса до `0xE0` монитор автоматически завершает ввод и закрывает файл.

## Пример полного сеанса: Вывод "1 2 3 4"

Допустим, необходимо ввести и запустить программу, которая последовательно выводит на индикаторы значения `1`, `2`, `3` и `4`, а затем автоматически возвращается в монитор.
Стартовый адрес всегда `0x10`.

Исходный код программы:

```text
ADDR  OPCODES    MNEMONIC    COMMENTS
-------------------------------------------------------------------------
10    F 8 F 3    LDP 0xF3    ; X:Y = 0xF3 (Указатель на DISP_3)
13    0 1        LDI 0x1     ; A = 1
15    2          STR         ; Запись 1 в DISP_3
16    7          DEX         ; X:Y = 0xF2 (Указатель на DISP_2)
17    0 2        LDI 0x2     ; A = 2
19    2          STR         ; Запись 2 в DISP_2
1A    7          DEX         ; X:Y = 0xF1 (Указатель на DISP_1)
1B    0 3        LDI 0x3     ; A = 3
1D    2          STR         ; Запись 3 в DISP_1
1E    7          DEX         ; X:Y = 0xF0 (Указатель на DISP_0)
1F    0 4        LDI 0x4     ; A = 4
21    2          STR         ; Запись 4 в DISP_0
22    F 9        BOOT        ; Возврат в Nano-Monitor (опкод F9)
```

Поскольку код `F` аппаратно используется загрузчиком монитора как escape-символ, каждый оригинальный ниббл `F` должен быть введен как двойное нажатие `FF`:

```text
A
FF 8 FF 3 0 1 2 7 0 2 2 7 0 3 2 7 0 4 2 FF 9 F 0
```

После ввода финального терминатора `F0` режим загрузки завершён, индикатор `DISP_0` сменится обратно на `0`.

Запуск:

```text
B
```

Процессор мгновенно перейдет в User Mode и выполнит код. Вы увидите на индикаторах кратковременное отображение `1234`, после чего инструкция `BOOT` (`F9`) немедленно вернет управление монитору (младший индикатор `DISP_0` сменится на `0`, показывая готовность к новым командам).

## Команды Nano-Monitor

```text
A ... F0    Load program (Ручная запись в User RAM начиная с 0x10)
B           Run program  (Безусловный переход на 0x10)
C           Tape load    (Авто-чтение файла с накопителя в User RAM)
D ... F0    Dump load    (Ручной ввод в User RAM с записью на накопитель)
```
