# Проект NC-1: 4-битный CPU и Эмулятор

**NC-1** — это минималистичный 4-битный микропроцессор с набором команд переменной длины (Variable-Length ISA, v4.5), спроектированный для образовательных целей, экспериментов с ПЛИС (FPGA), изучения цифровой логики и разработки программных эмуляторов. 

Данный репозиторий содержит полную техническую спецификацию архитектуры, исходный код ROM-монитора (Nano-Monitor), а также визуальный программный эмулятор аппаратно-отладочной платы, написанный на Python. Архитектура делает упор на экстремально высокую плотность кода и минимальный аппаратный размер, оставаясь при этом достаточно выразительной для поддержки встроенного Nano-Monitor, пользовательских приложений и периферии с отображением в память (MMIO).

## Ключевые особенности архитектуры (v4.5)

* **4-битная архитектура** с 8-битной шиной адреса (512 нибблов общего пространства: 256 ROM + 256 RAM).
* **Двухбанковая Гарвардская архитектура:** Раздельные банки ROM (Системный банк / Nano-Monitor, `M=1`) и RAM (Пользовательский банк, `M=0`).
* **Variable-Length ISA (1..4 ниббла):** Высочайшая плотность кода благодаря 1-ниббловым операциям работы с памятью (`LDR`, `STR`), стеком (`PHA`, `PLA`) и 16-битным указателем (`INX`, `DEX`). Относительные переходы (`JZR`, `JCR`, `JR`) используют знаковые 4-битные смещения (-8..+7).
* **Страничный аппаратный стек:** 4-битный физический указатель стека (`SP`) аппаратно привязан к странице RAM `0xE0..0xEF` (вызовы `CAL` и контекст `PHA/PLA`). Переполнение стека закольцовано по модулю 16.
* **Аппаратное переключение банков (`XBNK`):** Инструкция смены контекста исполнения между ROM и RAM (инверсия флага `M`) без изменения траектории `PC` и модификации флагов АЛУ (Z, C).
* **Механизм Shadow Write (Теневая запись):** Все операции записи (`STR`, `PHA`, `CAL`) аппаратно направляются исключительно в RAM независимо от состояния флага исполнения банка. Это позволяет коду из системного ROM инициализировать пользовательское ОЗУ и использовать стек.
* **Кросс-банковое чтение (`LDRA`):** Аппаратный механизм чтения данных из альтернативного банка памяти (RAM из ROM или ROM из RAM) без смены режима исполнения.
* **Ортогональный регистровый файл:** Прямой доступ к 8 физическим 4-битным регистрам: `A`, `B`, `X`, `Y`, `SP`, `FL`, `PCH`, `PCL`. Прямая запись в `PCL` вызывает немедленный переход.
* **Периферия MMIO (`0xF0..0xFF`):** Прямое управление 7-сегментными дисплеями, матричной клавиатурой, аудио, генератором случайных чисел и синхронным потоковым накопителем (Mass Storage).
* **Программный сброс (`BOOT`):** Аппаратная инструкция для мгновенной передачи управления Nano-Monitor (аппаратная установка PC=`0x00`, SP=`0xF`, M=`1`).

## Организация адресного пространства (0x00–0xFF)

| Адрес (Hex) | Зона памяти | Доступ | Описание |
|---|---|---|---|
| `00` | Reset Entry | Аппаратный | Аппаратный вектор сброса. Стартовая точка Nano-Monitor. |
| `01` – `0x0F` | Zero Page | ROM / RAM | Область памяти для кода или данных. |
| `10` – `0xDF` | Program Space | ROM / RAM | Основная область пользовательского кода (COM-area, макс. 208 нибблов). |
| `E0` – `0xEF` | Hardware Stack | RAM / ROM | Страница аппаратного стека (в RAM). Пользовательский код не должен загружаться в эту область в RAM. В ROM данная область может безопасно хранить системный код. |
| `F0` – `0xFD` | MMIO Ports | Регистры I/O | Порты управления периферией (Дисплеи, Клавиатура, GPO/Аудио, Накопитель). |
| `FE` – `0xFF` | Reserved | Зарезервировано | Для будущей периферии или управления банками памяти |

## Программный эмулятор и отладочная плата

Проект включает полноценный эмулятор с графическим интерфейсом (GUI) для кросс-компиляции исходного кода, пошаговой отладки ассемблера и визуального тестирования архитектуры. 

**Системные требования:**
* Python 3.10 или новее.
* Библиотека PyQt.

**Запуск эмулятора:**
Для старта эмулятора в режиме отладочной платы перейдите в директорию `emu` и выполните скрипт:

```bash
cd emu
python nc1.py
```
