# NC-1 Nano-Monitor — Under the Hood & Low-Level Architectural Hacks

Документ описывает внутреннее устройство, аппаратные особенности, протоколы взаимодействия с периферией и низкоуровневые оптимизации (хаки) прошивки **Nano-Monitor** для 4-битного процессора **NC-1 (версия спецификации v4.4)**.

---

## 1. Архитектурный контекст и системные ограничения

Микропроцессор NC-1 имеет гарвардскую архитектуру с переменной длиной команд (Variable-Length ISA v4.4) и двухбанковой организацией памяти:
- **System ROM (ПЗУ)**: Хранит код ОС/монитора (при `FL.M = 1`).
- **User RAM (ОЗУ)**: Хранит данные и код пользователя (при `FL.M = 0`).

### Карта памяти и MMIO
Шина адреса 8-битная ($2^8 = 256$ ячеек/нибблов). 
Физическое пространство памяти распределено следующим образом:

| Диапазон адресов | Назначение | Доступность кода |
| :--- | :--- | :--- |
| `0x00` | Единый вектор сброса (Reset / BOOT) | Исполняемый код (ROM) |
| `0x01 .. 0x0D` | Program Space / System Area | Исполняемый код (ROM) |
| `0x0E .. 0x0F` | Trampoline Region (`RUN_XBNK`) | Исполняемый код (ROM) |
| `0x10 .. 0xDF` | User Program Space (COM-зона) | Исполняемый код пользователя (RAM) |
| `0xE0 .. 0xEF` | Hardware Stack (Аппаратный стек) | Физический стек `CAL`/`RET`/`PHA`/`PLA` (RAM) |
| `0xF0 .. 0xFD` | Extended MMIO (Периферия) | **Заблокировано под I/O (`Is_MMIO = 1`)** |
| `0xFE .. 0xFF` | Reserved | Зарезервировано|

> **Критическое ограничение ROM:** При доступе к адресам `0xF0..0xFF` аппаратный декодер адресов (MMU) генерирует сигнал `Is_MMIO = 1`, блокирующий выборку инструкций из ПЗУ. Таким образом, **максимальный непрерывный объем кода монитора ограничен 240 нибблами (`0x00..0xEF`)**.

## 2. Аппаратные хаки и низкоуровневые оптимизации (ISA v4.4)

### 2.1. Концепция COM-формата (Фиксированный адрес `0x10`)
В ранних версиях монитора оператор был обязан вводить двузначный адрес перед командами `LOAD` и `RUN`. Переход на фиксированный базовый адрес `0x10` (по аналогии с `.com`-файлами в MS-DOS) позволил добиться ключевых преимуществ:
1. **Исключение кода парсинга адреса:** Высвобождено более 35 нибблов ROM.
2. **Ликвидация race conditions регистров:** Отпала необходимость хранить промежуточный адрес в регистровой паре `X:Y` или Zero Page между операциями чтения с клавиатуры.
3. **Прямая инициализация адреса:** Режим `LOAD` выставляет стартовый адрес записи в ячейки дисплея `DISP_3` и `DISP_2` через команды `LDP 0xF3` и single-nibble декремент `DEX`.

---

### 2.2. Паттерн «Трамплин» (Trampoline) и переключение банков через `XBNK`
Инструкция `XBNK` (`F7`) инвертирует бит `FL.M`, переключая банк выборки инструкций между System ROM (`M=1`) и User RAM (`M=0`). Для предотвращения рассогласования счётчика команд (`PC`) используется специальная область трамплина по адресу `0x0E`:

```asm
ORG 0x0E
RUN_XBNK:
    XBNK    ; Инвертирует M: 1 -> 0.
            ; Следующий такт выборки инструкции произойдет из User RAM по адресу 0x10
```

При выполнении команды `RUN` монитор делает переход `JMP RUN_XBNK`. Инструкция `XBNK` исполняется на адресе `0x0E` в ROM, переключает CPU в банк User RAM, и следующая инструкция считывается из `RAM[0x10]`, обеспечивая атомарный запуск пользовательской программы.

---

### 2.3. Аппаратный возврат в монитор (`BOOT` / `F9`)
В ISA v4.4 взамен программных прерываний `SWI` внедрена специализированная 2-ниббловая инструкция `BOOT` (`F9`). 
При выполнении `BOOT` в пользовательском коде аппаратная логика CPU моментально сбрасывает контекст:
- `PC = 0x00`
- `SP = 0xF`
- `M = 1` (активируется System ROM)

Это мгновенно передает управление вектору `0x00` в ROM-мониторе без использования дополнительных промежуточных регистров.

---

### 2.4. Поведение флагов АЛУ и отмена "мертвых зацикливаний" при поллинге I/O
В архитектуре NC-1 v4.4 инструкции пересылки и шинного обмена (`LDR`, `STR`, `LDI`, `MOV`, `LDP`) **не изменяют регистр флагов (FL)**. Флаги `Z` (Zero) и `C` (Carry) обновляются исключительно арифметическими инструкциями (`ADD`, `SUB`, `AND`, `XOR`, `INC A`, `DEC A`, `INX`, `DEX`).

#### Оптимизация поллинга клавиатуры
Порт статуса клавиатуры `0xF4` (`GPI_KBD`) использует только бит 0 (1 = кнопка нажата, 0 = кнопка отпущена).

1. **Ожидание нажатия (`WAIT_PRESS`):**
   ```asm
   WAIT_PRESS:
       LDR             ; Чтение GPI_KBD. Флаги не меняются!
       AND B           ; A = A & B (где B = 0x1). АЛУ обновляет Z-флаг.
       JZR WAIT_PRESS  ; Короткий переход (-5 нибблов), если Z=1 (кнопка не нажата)
   ```

2. **Ожидание отпускания (`WAIT_RELEASE`):**
   Для корректного обновления флага `Z` при переходе бита 0 из `1` в `0` применяется вычитание маски `SUB B`:
   ```asm
   WAIT_RELEASE:
       LDR             ; A = 0x1 (нажата) или 0x0 (отпущена)
       AND B           ; Изоляция бита 0
       SUB B           ; Если кнопка зажата: 1 - 1 = 0 -> Флаг Z = 1
       JZR WAIT_RELEASE; Короткий переход (-7 нибблов), пока Z = 1
   ```

---

### 2.5. Защелкивание клавиатурного регистра `0xF5`
Аппаратный контроллер клавиатуры NC-1 содержит встроенный D-триггер (Hardware Latch).

- При нажатии клавиши её 4-битный hex-код защелкивается в регистре `0xF5` (`KBD_CODE`).
- **Критическая фича периферии:** Регистр `0xF5` сохраняет значение нажатой клавиши даже после того, как физическая кнопка отпущена и бит статуса в `0xF4` сбросился в `0`.

Считывание кода происходит по цепочке: смещение с `0xF4` на `0xF5` выполняется single-nibble инструкцией `INX`, прочитанный код сразу отправляется в аппаратный стек через `PHA`, а извлекается обратно через `PLA` уже после подтверждения отпускания клавиши.

---

### 2.6. Однониббловые инструкции управления указателем (`INX`/`DEX`) и стеком (`PHA`/`PLA`)
ISA v4.4 вводит однониббловые опкоды для частых операций:
- `INX` (`0x6`) / `DEX` (`0x7`) — инкремент и декремент адресной пары `X:Y`.
- `PHA` (`0x4`) / `PLA` (`0x5`) — запись в аппаратный стек и извлечение из него.

Благодаря этому навигация между смежными портами MMIO (`DISP_3` `0xF3`, `DISP_2` `0xF2`, `DISP_1` `0xF1`, `DISP_0` `0xF0`) выполняется без повторного использования 4-ниббловой команды `LDP`:
```asm
    LDP 0xF3
    LDI 0x1
    STR         ; DISP_3 = 1
    DEX         ; X:Y атомарно становится 0xF2
    LDI 0x0
    STR         ; DISP_2 = 0
```

---

### 2.7. Динамическая индикация (Dynamic Feedback Overlay)
Монитор реализует визуальный контроль содержимого памяти и ввода в реальном времени.

1. **Пассивный режим (чтение RAM):** В `LOAD_LOOP` подпрограмма `SET_PTR` выгружает данные из User RAM (`LDRA`), и они отображаются на `DISP_1` (`0xF1`).
2. **Активный режим (удержание клавиши):** Внутри `GETKEY` в момент фиксации нажатия прочитанный код из `0xF5` сразу выводится на `DISP_1`:
   ```asm
   DEX
   DEX
   DEX
   DEX         ; X:Y = 0xF1
   STR         ; DISP_1 = код зажатой клавиши (визуальный оверлей)
   ```
3. **Фиксация:** После отпускания клавиши сохраненный в стеке код восстанавливается (`PLA`), записывается в User RAM по текущему адресу через `STR`, и адрес инкрементируется в `ADVANCE`.

---

### 2.8. Безопасная настройка указателей (`SET_PTR`) без разрушения MMIO-адреса
Для чтения текущего адреса из регистров индикации `DISP_3` (`0xF3`) и `DISP_2` (`0xF2`) нельзя напрямую обновлять регистр `X`, так как запись в `X` мгновенно сдвигает указатель `X:Y` из области MMIO в целевую область RAM.

Для предотвращения порчи адреса используется аппаратный стек (`PHA`/`PLA`):
```asm
SET_PTR:
    LDP 0xF3
    LDR
    PHA         ; Сохранение PCH в стек (не перезаписывая X!)
    DEX         ; X:Y корректно смещается на 0xF2 (DISP_2)
    LDR
    MOV Y, A    ; Y = PCL
    PLA         ; Извлечение PCH из стека
    MOV X, A    ; X = PCH (указатель X:Y сформирован)
    LDRA        ; Чтение User RAM по адресу X:Y в аккумулятор A
    RET
```

---

### 2.9. Относительные переходы (`JZR`, `JCR`)
В ISA v4.4 внедрены 2-ниббловые команды относительного перехода с 4-битным знаковым смещением (`[-8, +7]` нибблов).

Подпрограмма `ADVANCE` использует `JCR` для обработки переноса старшего полубайта адреса:
```asm
ADVANCE:
    LDP 0xF2
    LDR
    INC A       ; Вычисляет A + 1, обновляет флаги Z и C
    STR
    JCR ADV_HIGH; 2-ниббловый переход при C=1 (переполнение PCL)
    RET
```

### 2.10. Детерминированный Escape-автомат
Так как код `F` на клавиатуре совпадает с префиксом расширенных инструкций `EXT`, последовательность `F0` используется в качестве признака окончания загрузки.

Протокол `ESCAPE` реализован в виде детерминированного конечного автомата:
1. Первое нажатие `F` переводит монитор в ветку `ESCAPE`.
2. Ввод второго символа `0` (`F0`) сбрасывает режим и возвращает монитор в `MON_INIT`.
3. Ввод второго символа `F` (`FF`) вызывает абсолютный прыжок `JZ WRITE_B`. В регистре `B` уже зафиксирован код `0xF`, благодаря чему ровно один литерал `F` записывается в RAM, адрес инкрементируется, и загрузчик возвращается в `LOAD_LOOP`.
4. Ввод любого другого невалидного символа (например, `FC`) игнорируется, и совершается `JMP LOAD_LOOP` без изменения памяти и адреса.
