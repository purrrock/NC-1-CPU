# NC-1 Nano-Monitor — Under the Hood & Low-Level Architectural Hacks

Документ описывает внутреннее устройство, аппаратные особенности, протоколы взаимодействия с периферией и низкоуровневые оптимизации (хаки) прошивки **Nano-Monitor** для 4-битного процессора **NC-1 (версия спецификации v4.5)**.

---

## 1. Архитектурный контекст и системные ограничения

Микропроцессор NC-1 имеет гарвардскую архитектуру с переменной длиной команд (Variable-Length ISA v4.5) и двухбанковой организацией памяти:
- **System ROM (ПЗУ)**: Хранит код ОС/монитора (при `FL.M = 1`).
- **User RAM (ОЗУ)**: Хранит данные и код пользователя (при `FL.M = 0`).

### Карта памяти и MMIO
Шина адреса 8-битная ($2^8 = 256$ ячеек/нибблов). 

> **Критическое ограничение ROM:** При доступе к адресам `0xF0..0xFF` аппаратный декодер адресов (MMU) генерирует сигнал `Is_MMIO = 1`, блокирующий выборку инструкций из ПЗУ. Таким образом, **максимальный непрерывный объем кода монитора ограничен 240 нибблами (`0x00..0xEF`)** при условии неиспользования стека. Если использовать стек, то 224.

## 2. Аппаратные хаки и низкоуровневые оптимизации (ISA v4.5)

### 2.1. Концепция COM-формата (Фиксированный адрес `0x10`)
В отличие от классических мониторов, требующих ввода адреса назначения, Nano-Monitor использует фиксированный базовый адрес `0x10` (по аналогии с `.com`-файлами в MS-DOS):
1. **Исключение кода парсинга адреса:** .
2. **Ликвидация race conditions регистров:** Отпала необходимость хранить промежуточный адрес в регистровой паре `X:Y` или Zero Page между операциями чтения с клавиатуры.
3. **Отображение адреса на MMIO:** Инициализация адреса записи `0x10` одновременно задает состояние аппаратных индикаторов `DISP_3` (`0xF3`) и `DISP_2` (`0xF2`).

## 3. Арифметика парсинга команд (`WAIT_CMD`)

Для обработки 4 команд управления (`A` = LOAD, `B` = RUN, `C` = TAPE, `D` = DUMP) используется свойства 4-битного кольцевого вычитания (Modulo 16):

```asm
WAIT_CMD:
    CAL GETKEY          ; Чтение скан-кода клавиши в регистр B
    LDI 0xA             ; Загрузка баз-кода 'A' (0xA)
    SUB B               ; A = 0xA - B. Если наката 'A', A = 0 (Z = 1)
    JZ LOAD_INIT        ; Кнопка A -> Ручной ввод
    
    INC A               ; A = (0xA - B) + 1. Если была 'B' (0xB), A станет 0 (Z = 1)
    JMP RUN_XBNK        ; Кнопка B -> Запуск из RAM
    
    INC A               ; Если была 'C' (0xC), A станет 0 (Z = 1)
    JZ TAPE_LOAD_INIT   ; Кнопка C -> Авто-загрузка с флешки
    
    INC A               ; Если была 'D' (0xD), A станет 0 (Z = 1)
    JZ DUMP_INIT        ; Кнопка D -> Ввод с дампом на флешку
    
    BOOT                ; Любая другая кнопка -> Сброс
```

**Экономический эффект:** Отсутствие необходимости повторно загружать константы `0xB`, `0xC`, `0xD` через `LDI` экономит **19 нибблов** памяти ROM.

## 4. Ультра-компактный поллинг клавиатуры (Hardware Port Hack)

В порту `0xF4` (`KBD_STAT`) старшие неиспользуемые биты (Bits 1..3) аппаратно подтянуты к `0`. Бит 0 отражает физическое состояние кнопки (`1` — зажата, `0` — отпущена).

Благодаря этому чтение порта инструкцией `LDR` возвращает чистый `0x00`.

## 5. Прямые битовые проверки через `XOR`

В ISA v4.5 сравнение значений через `XOR B` позволяет выполнять быструю проверку на точное соответствие битовой маске за 1 инструкцию:

1. **Проверка режима накопителя (`STORAGE_CMD`):**
   - В режиме `TAPE` статус порта равен `0x1` (`READY=1`, `MODE=0`). Выполнение `LDI 0x1` + `XOR B` дает `0` (`Z = 1`), только если режим активен.
   - В режиме `DUMP` статус порта равен `0x3` (`READY=1`, `MODE=1`). Выполнение `LDI 0x3` + `XOR B` гарантирует проверку двух флагов одновременно.
2. **Защита границ аппаратного стека (`ADV_HIGH`):**
   - Проверка достижения старшим полубайтом адреса (`PCH`) границы `0xE0`:
     ```asm
     LDI 0xE
     XOR B              ; Если PCH == 0xE, B ^ 0xE = 0 -> Z = 1
     JZ CLOSE_FILE      ; Экстренное закрытие и возврат
     ```

## 6. Объединенная инициализация накопителя (`SET_STORAGE`)

Для минимизации дублирования кода процедуры `TAPE_LOAD_INIT` и `DUMP_INIT` объединены по принципу сквозного выполнения (Fall-through):

```asm
TAPE_LOAD_INIT:
    LDI 0x1             ; Режим чтения: MOTOR=1, MODE=0
    JR SET_STORAGE      ; Короткий относительный переход (+2 ниббла)
DUMP_INIT:
    LDI 0x3             ; Режим записи: MOTOR=1, MODE=1
SET_STORAGE:
    MOV B, A
    LDP 0xF9            ; STORAGE_CMD
    MOV A, B
    STR
```

## 7. Протокол синхронного накопителя (Tape Load & Dump Stream)

Взаимодействие с внешним накопителем осуществляется через регистры MMIO `0xF8` (`STORAGE_DAT`) и `0xF9` (`STORAGE_CMD`).

### Структура регистра `STORAGE_CMD` (`0xF9`)
- **Bit 0 (`READY`)**: `1` — накопитель готов.
- **Bit 1 (`EOF`)**: `1` — достигнут конец файла (End of File).
- **Bit 2 (`MODE`)**: `0` — чтение, `1` — запись.
- **Bit 3 (`MOTOR`)**: `1` — привод включен, `0` — остановка.

### Автоматический потоковый цикл (`TL_LOOP`)
При чтении файла монитор в цикле проверяет комбинацию флагов `READY=1` и `EOF=1` (маска `0x3`):

```asm
TL_LOOP:
    LDP 0xF9
    LDR
    MOV B, A
    LDI 0x3             ; Маска битов READY и EOF
    XOR B               ; Z=1 только при достижении EOF
    JZ CLOSE_FILE       ; Автоматическое закрытие и возврат
    
    DEX                 ; X:Y = 0xF8 (STORAGE_DAT)
    LDR                 ; Чтение следующего ниббла
    MOV B, A
    CAL SET_PTR         ; Установка курсора User RAM
    MOV A, B
    STR                 ; Атомарная запись в RAM
    CAL ADVANCE
    JMP TL_LOOP
```

## 8. Безопасное формирование указателя адреса (`SET_PTR`)

Курсор текущего адреса чтения/записи хранится в регистрах индикаторов `DISP_3` (`0xF3`, старший ниббл) и `DISP_2` (`0xF2`, младший ниббл). Для считывания адреса без разрушения текущих регистров MMIO подпрограмма `SET_PTR` использует регистр `B` как временный буфер:

```asm
SET_PTR:
    LDP 0xF3
    LDR
    MOV B, A            ; Сохранение PCH в регистре B
    DEX                 ; X:Y = 0xF2 (DISP_2)
    LDR
    MOV Y, A            ; 
    MOV A, B
    MOV X, A            ;
    LDRA                ; Чтение текущей ячейки RAM по сформированному X:Y
    RET
```

## 9. Относительные переходы и ограничения смещений (ISA v4.5)

Инструкции относительных переходов (`JR`, `JZR`, `JCR`) занимают **2 ниббла** и используют 4-битное знаковое смещение в диапазоне **от -8 до +7 нибблов** относительно адреса следующей инструкции (`PC_next`).

### Правила применения в мониторе:
- **Короткие петли (Relative):** Операции ожидания флагов (`WAIT_RDY_LOOP`, `WAIT_P`, `WAIT_R`) и локальные ветвления (`JCR ADV_HIGH`) укладываются в диапазон и кодируются 2 нибблами.
- **Длинные циклы (Absolute):** Циклы `LOAD_LOOP`, `TL_LOOP`, `IS_ECHO` и межблочные переходы превышают дистанцию в 7 нибблов и кодируются 4-ниббловой инструкцией `JMP`.

## 10. Детерминированный Escape-автомат (`ESCAPE`)

Код `F` совпадает с префиксом расширенных инструкций `EXT`. Для корректной обработки бинарных данных используется двухсимвольный автомат:

1. Первое нажатие `F` переводит монитор в процедуру `ESCAPE`.
2. Команда `F0` (`F` + `0`) распознается как конец файла:
   ```asm
   ESCAPE:
       CAL GETKEY
       LDI 0x0
       XOR B            ; Если введен '0', B ^ 0 = 0 -> Z = 1
       JZ CLOSE_FILE    ; Закрыть файл и выйти в BOOT
   ```
3. Команда `FX` (где `X` != `0`) передает управление на `WRITE_B`, записывая ниббл `X` как литерал (например, `FF` записывает значение `0xF`).
