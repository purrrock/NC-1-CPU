# NC-1 Nano-Monitor — Under the Hood & Low-Level Architectural Hacks

Документ описывает внутреннее устройство, аппаратные особенности, протоколы взаимодействия с периферией и низкоуровневые оптимизации (хаки) прошивки **Nano-Monitor** для 4-битного процессора **NC-1 (v4.2)**.

---

## 1. Архитектурный контекст и системные ограничения

Микропроцессор NC-1 имеет гарвардскую архитектуру с двухбанковой организацией памяти:
- **System ROM (ПЗУ)**: Хранит код ОС/монитора (при `FL.M = 1`).
- **User RAM (ОЗУ)**: Хранит данные и код пользователя (при `FL.M = 0`).

### Карта памяти и MMIO
Шина адреса 8-битная ($2^8 = 256$ ячеек/нибблов). 
Физическое пространство распределено следующим образом:

| Диапазон адресов | Назначение | Доступность кода |
| :--- | :--- | :--- |
| `0x00` | Единая точка входа (Reset / SWI) | Исполняемый код |
| `0x01 .. 0x0F` | Zero Page (системное состояние ОС) | Исполняемый код / данные |
| `0x10 .. 0xDF` | User Program Space (COM-зона) | Исполняемый код пользователя |
| `0xE0 .. 0xEF` | Hardware Stack (Аппаратный стек) | Физический стек `CAL`/`RET` |
| `0xF0 .. 0xFF` | Extended MMIO (Периферия) | **Заблокировано под I/O** |

> **Критическое ограничение ROM:** Несмотря на физический объем банка в 256 нибблов, аппаратный декодер адресов (MMU) при доступе к `0xF0..0xFF` генерирует сигнал `Is_MMIO = 1`, блокирующий выборку инструкций из ПЗУ. Таким образом, **максимальный непрерывный объем кода монитора ограничен 240 нибблами (`0x00..0xEF`)**.

## 2. Аппаратные хаки и низкоуровневые оптимизации

### 2.1. Концепция COM-формата (Фиксированный адрес `0x10`)
В ранних версиях монитора оператор был обязан вводить двузначный адрес перед командами `LOAD` и `RUN`. Переход на фиксированный базовый адрес `0x10` (по аналогии с `.com`-файлами в MS-DOS) позволил добиться ключевых преимуществ:
1. **Исключение кода парсинга адреса:**.
2. **Ликвидация race conditions регистров:** Отпала необходимость хранить промежуточный адрес в регистровой паре `X:Y` или Zero Page между операциями чтения с клавиатуры.
3. **Безопасный переход в User Mode:** Команда `RUN` выполняет прямую инициализацию счетчика команд:
   ```asm
   LDI 0x1
   MOV PCH, A    ; Защелкиваем старший ниббл PCH = 1
   LDI 0x0
   MOV FL, A     ; Сброс M=0 (переключение банков памяти ROM -> RAM)
   MOV PCL, A    ; PCL = 0. Запись в PCL инициирует прыжок на 0x10 в User RAM
   ```

### 2.2. Различение Cold Boot и SWI через вектор `0x00`
Процессор NC-1 имеет единый вектор для аппаратного сброса (`Reset`) и программного прерывания (`SWI`/`SYS 4`). В обоих случаях `PC` устанавливается в `0x00`, а режим переключается в `M = 1` (System Mode).

Различение контекстов выполняется анализом флага `R` (бит 3 регистра `FL`):
- При аппаратном Reset: аппаратная логика CPU устанавливает `FL.R = 1`.
- При выполнении `SWI`: аппаратная логика сохраняет текущий `R` (обычно `0`).

**Диспетчер входа:**
```asm
ENTRY:
    LDI 0x8         ; Загрузка маски 1000b (проверка бита 3)
    MOV B, A
    MOV A, FL       ; Чтение статуса CPU
    AND B           ; АЛУ вычисляет A & B и обновляет флаг Z
    JZ CMD_LOOP     ; Если Z=1 (R=0) -> возврат из пользовательского SWI
    
    LDI 0x4         ; Если R=1 (Reset) -> сброс R, сохранение M=1 (0100b)
    MOV FL, A
```

### 2.3. Поведение флагов АЛУ
В архитектуре NC-1 инструкции пересылки и шинного обмена (`LDR`, `STR`, `LDI`, `MOV`) **не изменяют регистр флагов (FL)**. Флаги `Z` (Zero) и `C` (Carry) обновляются исключительно арифметико-логическим устройством (инструкции `ADD`, `SUB`, `AND`, `OR`, `XOR`, `INC`, `DEC`).

#### Проблема «Мертвого зацикливания» (Deadlock)
Если выполнить:
```asm
K_WAIT:
    LDR             ; Загружает значение из MMIO в A. Флаг Z НЕ МЕНЯЕТСЯ!
    JZ K_WAIT       ; JZ анализирует "мусорный" флаг Z от предыдущей операции АЛУ!
```
Процессор зациклится навсегда, так как `LDR` не обновляет `Z`.

#### Оптимизация обработки сигнала отпускания клавиши
Порт статуса клавиатуры `0xF4` (`GPI_KBD`) использует только бит 0 (1 = кнопка нажата, 0 = кнопка отпущена). Биты 1–3 аппаратно заземлены (`0`).

Для ожидания нажатия применяется пропускание через АЛУ:
```asm
    AND B           ; A = A & 1 (где B = 0x1). Явно обновляет флаг Z
    JZ K_WAIT_P
```

Для ожидания отпускания клавиши используется вычитание маски `SUB B`:
```asm
K_WAIT_R:
    LDR             ; A = 0x1 (нажата) или 0x0 (отпущена)
    AND B           ; Изоляция бита 0
    SUB B           ; Если кнопка нажата: 1 - 1 = 0 -> Флаг Z = 1
    JZ K_WAIT_R     ; Пока Z = 1 (кнопка удерживается), ждем
```

### 2.4. Защелкивание клавиатурного регистра `0xF5`
Аппаратный контроллер клавиатуры NC-1 содержит встроенный D-триггер (Hardware Latch). 

- При нажатии клавиши её 4-битный hex-код защелкивается в регистре `0xF5` (`KBD_CODE`).
- **Критическая фича периферии:** Регистр `0xF5` сохраняет значение нажатой клавиши даже после того, как физическая кнопка отпущена и бит статуса в `0xF4` сбросился в `0`.

Это позволяет считывать код клавиши *после* цикла ожидания отпускания (`KEY_WAIT_RELEASE`), что гарантирует защиту от дребезга контактов и исключает повторный ложный ввод без применения сложных программных таймеров.

### 2.5. Динамическая индикация (Dynamic Feedback)
Монитор реализует прозрачный визуальный контроль содержимого памяти и ввода в реальном времени.

1. **Пассивный режим (чтение RAM):** Перед считыванием клавиши подпрограмма `LOAD_LOOP` вызывает `SET_PTR` и исполняет `LDRA`. Данные из User RAM по текущему адресу выгружаются на индикатор `DISP_1` (`0xF1`).
2. **Активный режим (удержание клавиши):** Внутри `GETKEY` в момент фиксации нажатия прочитанный код из `0xF5` сразу же переписывает `DISP_1`:
   ```asm
   LDI 0x1
   MOV Y, A
   STR             ; DISP_1 = код зажатой клавиши (визуальный оверлей)
   ```
3. **Фиксация:** После отпускания клавиши сохраненный код возвращается в вызывающий контекст, записывается в User RAM через `STR`, и адрес инкрементируется.

### 2.6. Ортогональность АЛУ и работа с указателями (`ADVANCE`)
В архитектуре NC-1 унарные арифметические инструкции (`INC`, `DEC`) обладают полной ортогональностью по отношению к регистру флагов (`FL`). В отличие от некоторых винтажных 8-битных архитектур (например, Intel 8080), где инкремент не затрагивает флаг переноса (Carry), АЛУ NC-1 **жестко обновляет флаги Z и C** при каждой операции `INC` и `DEC`.

- При выполнении `INC Reg`, если результат превышает `0xF` (переполнение), аппаратно устанавливается `C = 1`.
- Если переполнения нет, флаг `C` гарантированно сбрасывается в `0`.

Эта архитектурная особенность делает вычисление 8-битных адресов (PCH:PCL) крайне элегантным. Подпрограмма `ADVANCE` просто инкрементирует младший полубайт (PCL, хранящийся в `DISP_2`) и проверяет флаг `C`. Благодаря тому, что `INC` сам очищает `C`, нам не нужно беспокоиться о "мусорных" флагах, оставшихся после предыдущих операций `SUB` в главном цикле `LOAD_LOOP`:

```asm
    INC B           ; Инкремент младшего ниббла (PCL)
    MOV A, B
    STR             ; Сохранение нового PCL в дисплейный регистр
    JC ADV_HIGH     ; Если произошло переполнение (0xF -> 0x0), инкрементируем PCH
```
Такой подход экономит ценное пространство в ROM, позволяя избежать громоздких конструкций вида `LDI 0x1; ADD B`.

### 2.7. Относительное управление указателем MMIO
Для сокращения размера кода вместо повторной загрузки `LDI 0xF; MOV X, A` и `LDI 0xN; MOV Y, A` подпрограммы используют относительно смещенный регистр `Y`. Так как все порты MMIO сгруппированы в диапазоне `0xF0..0xF5`, сдвиг между соседними регистрами выполняется командами `INC Y` и `DEC Y`:

```asm
    CAL GETKEY      ; При выходе из GETKEY регистр Y гарантированно равен 4 (0xF4)
    DEC Y           ; Y становится равным 3 (автоматический указатель на DISP_3!)
    STR             ; Запись старшего полубайта адреса
```
Это сэкономило 4 ниббла на каждом обращении к периферии.

### 2.8. Escape-протокол загрузки данных
Так как код `F` на клавиатуре совпадает с опкодом инструкций семейства `SYS`, последовательность `F0` выбрана в качестве аппаратного терминатора загрузки (соответствует инструкции `HLT`).

Для обеспечения возможности записи литерала `0xF` в память используется простой двухсимвольный escape-автомат:

```text
Входной поток -> [GETKEY]
                     |
                     +-- Код != F -------> Запись в RAM
                     |
                     +-- Код == F -------> [GETKEY (второй символ)]
                                               |
                                               +-- Код == 0 -> Выход в CMD_LOOP
                                               |
                                               +-- Код != 0 -> Запись 0xF в RAM,
                                                               перенос символа
```
