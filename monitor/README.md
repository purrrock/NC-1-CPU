# NC-1 Nano-Monitor

Nano-Monitor — минимальная ROM-мониторная программа для учебного 4-битного процессора NC-1.

Монитор позволяет с 16-клавишной hex-клавиатуры:

- запускать пользовательскую программу из User RAM;
- загружать бинарный файл с накопителя непосредственно в User RAM;
- вводить машинный код с клавиатуры с одновременной записью каждого nibble в User RAM и на накопитель.

Пользовательские программы загружаются начиная с адреса `0x10`, по аналогии с `.COM`-файлами DOS.

Nano-Monitor работает в System Mode (`M=1`) и размещается в System ROM. Область `0xE0..0xEF` физически является RAM-страницей аппаратного стека для пользовательского режима, поэтому пользовательский код не должен занимать эту область.

## Запуск

После аппаратного сброса NC-1 начинает выполнение с адреса `0x00`, где находится Nano-Monitor.

Монитор ожидает одну команду с клавиатуры.

Поддерживаются три команды:

| Клавиша | Команда | Назначение |
|---|---|---|
| `0` | `RUN` | Запустить программу из RAM с адреса `0x10` |
| `1` | `TAPE` | Загрузить файл с накопителя в RAM начиная с `0x10` |
| `2` | `DUMP` | Ввод с клавиатуры с одновременной записью в RAM и на накопитель |

Все остальные клавиши в командном режиме игнорируются.

## DUMP — ручной ввод с записью на накопитель

Нажмите:

```text
2
```

Монитор открывает накопитель в режиме записи и начинает ввод машинного кода с адреса `0x10`.

Каждый введённый nibble одновременно:

1. записывается в User RAM;
2. записывается в поток накопителя.

Стартовый адрес вводить не требуется.

Например, ввод:

```text
2
1 2 3 4 5 6
F 0
```

запишет:

```text
RAM[0x10] = 0x1
RAM[0x11] = 0x2
RAM[0x12] = 0x3
RAM[0x13] = 0x4
RAM[0x14] = 0x5
RAM[0x15] = 0x6
```

Последовательность `F0` является признаком завершения ввода. Эти два nibble в программу не записываются.

После `F0` монитор закрывает файл и возвращается в командный режим.

### Как записать `F` как данные

Поскольку `F0` используется как признак конца ввода, для записи литерального `F` используется escape-последовательность:

```text
FF
```

То есть:

```text
FF
```

означает «записать один nibble `F`».

Например, чтобы в программу записать последовательность:

```text
F 4 1 2 F 0
```

нужно ввести:

```text
2
FF 4 1 2 FF 0 F 0
```

Последнее `F0` завершает ввод.

## TAPE — загрузка файла с накопителя

Нажмите:

```text
1
```

Монитор открывает накопитель в режиме чтения и автоматически считывает файл nibble за nibble.

Поток записывается в User RAM начиная с:

```text
0x10
```

Каждый полученный nibble записывается в следующую ячейку RAM.

При достижении конца файла монитор закрывает накопитель и возвращается в командный режим через `BOOT`.

Во время `TAPE` значение дисплеев не имеет функционального значения.

## RUN — запуск программы

Для запуска загруженной программы нажмите:

```text
0
```

С точки зрения пользователя выполнение программы начинается с:

```text
RAM[0x10]
```

Внутренне монитор использует специальный trampoline:

```text
ROM[0x0E] = XBNK
```

Последовательность запуска:

```text
RUN
 ↓
JMP RUN_XBNK
 ↓
ROM[0x0E]: XBNK
 ↓
M: 1 → 0
 ↓
следующая выборка инструкции из RAM[0x10]
```

Таким образом, `XBNK` переключает банк выборки инструкций, не изменяя траекторию `PC`, и первая инструкция пользовательской программы выполняется из `RAM[0x10]`.

## Индикация

Во время режима `DUMP` дисплеи используются для контроля вводимых данных:

```text
DISP_3 DISP_2 DISP_1 DISP_0
   адрес    ввод    режим
```

### DISP_0

Показывает текущий режим:

```text
2 = DUMP
```

Во время `RUN` и `TAPE` содержимое дисплеев не имеет функционального значения.

### DISP_3 : DISP_2

Показывают текущий адрес User RAM, используемый для записи.

После записи nibble адрес автоматически увеличивается.

Например, после записи в `RAM[0x10]` на дисплее появляется:

```text
0 1
```

что соответствует следующему адресу `0x11`.

### DISP_1

Во время нажатия клавиши показывает код последней нажатой клавиши.

Это позволяет визуально контролировать ввод hex-данных.

## Требования к пользовательской программе

Пользовательская программа должна находиться в User RAM и компилироваться с:

```asm
ORG 0x10
```

Основная область пользовательского кода:

```text
0x10 .. 0xDF
```

Адреса:

```text
0x00 .. 0x0F
```

также могут использоваться пользовательской программой для кода и данных. Nano-Monitor в данной версии не предоставляет API или системных функций, требующих сохранения этой области.

Области памяти User RAM:

```text
0x00 .. 0x0F   Zero Page
0x10 .. 0xDF   User Program / COM-area
0xE0 .. 0xEF   Hardware Stack
0xF0 .. 0xFF   MMIO
```

### Аппаратный стек

Область:

```text
0xE0 .. 0xEF
```

зарезервирована аппаратным стеком и используется инструкциями:

```text
CAL
RET
PHA
PLA
```

Пользовательская программа не должна загружать код или данные в эту область.

В результате максимальный размер загружаемой пользовательской программы из `0x10` составляет:

```text
0xD0 = 208 nibbles
```

## Возврат в Nano-Monitor

Пользовательская программа может вернуть управление монитору инструкцией:

```asm
BOOT
```

`BOOT`:

- устанавливает `M=1`;
- устанавливает `PC=0x00`;
- сбрасывает `SP=0xF`;
- передаёт управление Nano-Monitor.

После этого монитор снова ожидает команду:

```text
0 = RUN
1 = TAPE
2 = DUMP
```

Простейшая программа:

```asm
ORG 0x10
LDI 0x5
MOV B,A
BOOT
```

## Ограничения

Nano-Monitor предназначен для загрузки и запуска небольших учебных программ.

Не следует загружать пользовательский код или данные в:

```text
0xE0 .. 0xEF
```

поскольку эта область User RAM используется аппаратным стеком.

Максимальный безопасный диапазон пользовательской программы:

```text
0x10 .. 0xDF
```

или 208 nibble.

Область:

```text
0xF0 .. 0xFF
```

занята MMIO и не является областью пользовательской программы.

## Пример полного сеанса: вывод «4321»

Допустим, необходимо загрузить программу, которая выводит на четыре индикатора:

```text
4321
```

а затем останавливается.

Переходим в режим ввода:

```text
2
```

Стартовый адрес всегда `0x10`.

Исходный код программы:

```text
; Вывод 4, 3, 2, 1 на DISP_3..DISP_0

    F8 F 3        ; LDP 0xF3 — левый индикатор
    0 4           ; LDI 4

LOOP:
    2             ; STR — вывести A
    7             ; DEX — F3 -> F2 -> F1 -> F0
    9             ; DEC A — 4 -> 3 -> 2 -> 1 -> 0
    C 2           ; JZR EXIT — если A=0
    E 9           ; JR LOOP — назад на 7 nibble

EXIT:
    FF            ; HLT
```

Поскольку `F` используется монитором как начало escape-последовательности, каждый `F` исходной программы при ручном вводе кодируется двойным `F`.

Поэтому сеанс выглядит так:

```text
2
FF 8 FF 3 0 4 2 7 9 C 2 E 9 FF FF F 0
```

Здесь:

- `FF` → литеральный nibble `F`;
- `FF FF` → два последовательных nibble `F`, то есть инструкция `FF` (`HLT`);
- последнее `F0` — терминатор загрузки и в программу не записывается.

После ввода последнего:

```text
F 0
```

монитор закрывает накопитель и возвращается в командный режим.

Для запуска программы нажмите:

```text
0
```

Процессор переключится в User Mode и начнёт выполнение с `RAM[0x10]`.

На дисплеях будет показана последовательность:

```text
4321
```

после чего инструкция `HLT` остановит выполнение процессора.
